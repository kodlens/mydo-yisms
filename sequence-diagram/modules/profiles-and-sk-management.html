Module 02 · Sequence A

Youth Registry Directory, Drawer Inspection & Profile Updates

Covers how Youth update their own academic/personal data and how MYDO Staff and Administrators search, filter, inspect, moderate, and manage Youth records.

YouthMyProfileController StaffYouthProfileController AdminYouthProfileController 
sequenceDiagram
    autonumber
    actor Youth as Youth Member
    actor StaffAdmin as MYDO Staff / Admin
    participant UI as Portal / Workspace UI
    participant Ctrl as YouthProfile Controllers
    participant DB as MySQL (youth_profiles, barangays, activity_logs)

    Note over Youth, DB: 1. Youth Self-Service Profile Update
    Youth->>UI: Open /youth/my-profile & edit personal, address, or school details
    UI->>Ctrl: PUT /youth/my-profile
    Ctrl->>DB: Validate & update YouthProfile attributes
    Ctrl-->>UI: Return updated profile & flash confirmation

    Note over StaffAdmin, DB: 2. Staff & Admin Registry Search and Drawer Moderation
    StaffAdmin->>UI: Open Youth Profiles page & filter by search, barangay, year, or status
    UI->>Ctrl: GET /get-youth-profiles
    Ctrl->>DB: Query YouthProfile with province, city, barangay & approver
    Ctrl-->>UI: Return paginated Youth registry rows
    StaffAdmin->>UI: Click row to open Youth Profile Drawer (view School ID & credentials)
    opt Approve / Reject / Reset Youth Password (Admin)
        UI->>Ctrl: POST /approve, /reject, or /admin/youth-profiles/{id}/change-password
        Ctrl->>DB: Persist status or hashed password & write ActivityLog
        Ctrl-->>UI: Refresh Youth directory state
    end
Module 02 · Sequence B

SK Official Registration with Cascading PSGC Barangay Assignment

Shows how Staff (/staff/sk-officials) and Administrators (/admin/users when role = sk) assign an SK Position and Barangay Leading, and how that jurisdiction propagates across the SK Portal and Event Evidence modals.

OpenController (PSGC) StaffSkOfficialController AdminUserController SkDashboardController 
sequenceDiagram
    autonumber
    actor Registrar as MYDO Staff / Admin
    participant Modal as SK Registration / Manage User Modal
    participant OpenAPI as OpenController (PSGC)
    participant SkCtrl as StaffSkOfficial / AdminUser Controller
    participant DB as MySQL (users, provinces, cities, barangays)
    actor SK as SK Official

    Note over Registrar, DB: 1. Cascading Address Lookup in Registration Modal
    Registrar->>Modal: Open Register SK Official (or Select Role = SK OFFICIAL)
    Modal->>OpenAPI: GET /load-provinces
    OpenAPI->>DB: Query active provinces
    OpenAPI-->>Modal: Return Province options
    Registrar->>Modal: Select Province -> triggers City lookup
    Modal->>OpenAPI: GET /load-cities?provCode=...
    OpenAPI-->>Modal: Return City / Municipality options
    Registrar->>Modal: Select City -> triggers Barangay lookup
    Modal->>OpenAPI: GET /load-barangays?provCode=...&cityCode=...
    OpenAPI-->>Modal: Return Barangay options

    Note over Registrar, DB: 2. Persist SK Position & Barangay Jurisdiction
    Registrar->>Modal: Choose SK Position, Barangay Leading, optional Street & submit
    Modal->>SkCtrl: POST /staff/sk-officials (or POST /admin/users with role=sk)
    SkCtrl->>DB: Validate exists on provinces, cities, barangays & save User
    SkCtrl->>DB: ActivityLogger::log(sk_official.created with Position & Brgy. Name)
    SkCtrl-->>Modal: Return saved status & display Brgy. Name in directory table

    Note over SK, DB: 3. Downstream Barangay Propagation
    SK->>DB: Sign in & open /sk/dashboard
    DB-->>SK: HandleInertiaRequests & SkDashboardController load barangay.brgyDesc + scoped youth counts
    SK->>DB: Submit SkActivityEvidence on /sk/events-activities
    DB-->>Registrar: Staff/Admin sk-evidences endpoint displays SK Position + Brgy. Name badge
