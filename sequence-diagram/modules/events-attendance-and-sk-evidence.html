Module 04 · Sequence A

Event Publication, Youth Slot Registration & Participant Moderation

Covers how Staff and Administrators create/publish activities, how Youth join or cancel registrations under capacity constraints, and how Staff/Admin approve or withdraw sign-ups.

Staff / AdminEventActivityController YouthEventActivitiyController@join ActivityRegistration::scopeReservingSlot 
sequenceDiagram
    autonumber
    actor Organizer as MYDO Staff / Admin
    participant OrgUI as Staff / Admin Events UI
    participant EventCtrl as EventActivity Controllers
    participant YouthCtrl as YouthEventActivitiyController
    participant DB as MySQL (activities, activity_registrations)
    actor Youth as Youth Member

    Note over Organizer, DB: 1. Activity Creation & Featured Toggle
    Organizer->>OrgUI: Create Activity (Category, Venue, Schedule, Capacity, requires_approval)
    OrgUI->>EventCtrl: POST /events-activities (staff or admin prefix)
    EventCtrl->>DB: Generate unique slug, stamp published_at & insert Activity
    EventCtrl-->>OrgUI: Return 201 Created

    Note over Youth, DB: 2. Youth Registration with Capacity Protection
    Youth->>YouthCtrl: POST /youth/services/events-activities/{activity}/join
    YouthCtrl->>DB: Lock Activity row & count reservingSlot() registrations
    alt Activity is Full
        YouthCtrl-->>Youth: Reject join (Activity capacity reached)
    else Slot Available
        alt requires_approval == true
            YouthCtrl->>DB: Insert ActivityRegistration (status=pending)
        else Auto-Confirm (requires_approval == false)
            YouthCtrl->>DB: Insert ActivityRegistration (status=approved)
        end
        YouthCtrl-->>Youth: Confirm registration & unlock QR Event Pass if approved
    end

    Note over Organizer, DB: 3. Participant Review (Approve / Reject / Withdraw)
    Organizer->>OrgUI: Open /events-activities/{id}/participants
    OrgUI->>EventCtrl: PATCH /events-activities/{id}/participants/{registration}
    EventCtrl->>DB: Verify capacity & update status (approved or rejected + reason)
    EventCtrl-->>OrgUI: Return refreshed participant row & slots_left summary
Module 04 · Sequence B

Live QR Scanner & Manual Check-In + Audited Attendance Removal

Available in both Staff (/staff/events-activities/{id}/attendance) and Admin (/admin/events-activities/{id}/attendance), backed by row-level locking in ActivityAttendanceService and 12-second TanStack Query background polling.

Staff / AdminActivityAttendanceController ActivityAttendanceService QrScanner.tsx + ManualCodeEntry.tsx 
sequenceDiagram
    autonumber
    actor Youth as Youth Participant
    actor Operator as MYDO Staff / Admin
    participant TermUI as Attendance Check-in Terminal
    participant AttCtrl as ActivityAttendanceController
    participant Svc as ActivityAttendanceService
    participant DB as MySQL (attendances, registrations, activity_logs)

    Youth->>Operator: Present QR Event Pass (YD-XXXX-XXXX) or Student ID at venue
    Operator->>TermUI: Scan QR via BarcodeDetector camera or submit Manual Code
    TermUI->>AttCtrl: POST /events-activities/{id}/attendance (reference_code, method, remarks)
    AttCtrl->>Svc: recordAttendance(activity, code, method, operatorUser, remarks)

    Svc->>DB: Begin Transaction & lockForUpdate() on Activity + YouthProfile + Registration
    alt Invalid Code / Unapproved Registration / Duplicate Check-In
        Svc-->>AttCtrl: Throw ValidationException (duplicate / reference_code / activity)
        AttCtrl-->>TermUI: Return 422 JSON error
        TermUI-->>Operator: Show red Attendance Not Recorded alert card
    else Verified Approved Participant
        Svc->>DB: Insert ActivityAttendance (method=qr|manual, recorded_by=operator.id, attended_at=now)
        Svc-->>AttCtrl: Return attendance record + recomputed getSummary()
        AttCtrl-->>TermUI: Return 201 Created
        TermUI-->>Operator: Play audio chime, display Confirmed Check-in card & update Turnout %
    end

    opt Administrative Attendance Correction / Removal
        Operator->>TermUI: Click Remove on attendance row & enter required reason (min 5 chars)
        TermUI->>AttCtrl: DELETE /events-activities/{id}/attendance/{attendanceId} (reason)
        AttCtrl->>Svc: removeAttendanceWithAudit(activity, attendanceId, operatorUser, reason)
        Svc->>DB: Insert ActivityLog (action=activity_attendance.removed, old_values, reason)
        Svc->>DB: Delete ActivityAttendance row
        AttCtrl-->>TermUI: Return 200 OK + updated summary
    end
Module 04 · Sequence C

SK Official Event Photo & Narrative Evidence Pipeline

Traces how Sangguniang Kabataan Officials upload post-activity photo documentation and how Staff and Administrators inspect submissions tagged with the SK Official's Position and Barangay.

SkEventActivityController@storeEvidence Staff / AdminEventActivityController@skEvidences 
sequenceDiagram
    autonumber
    actor SK as SK Official
    participant SkUI as SK Events & Evidence Page
    participant SkCtrl as SkEventActivityController
    participant Disk as Public Storage Disk
    participant DB as MySQL (sk_activity_evidences, users, barangays)
    actor Reviewer as MYDO Staff / Admin

    SK->>SkUI: Select published Activity, upload 1-10 photos (/temp-upload) & enter narrative
    SkUI->>SkCtrl: POST /sk/events-activities/{activity}/evidence
    SkCtrl->>Disk: Verify PNG/JPG MIME & move to upfiles/sk-evidences/activity-{id}/sk-{user_id}
    SkCtrl->>DB: Create SkActivityEvidence (activity_id, user_id, description, photos)
    SkCtrl-->>SkUI: Return 200 OK & update my_evidences list

    Reviewer->>DB: Click SK Evidence button in Staff or Admin Events Directory
    DB-->>Reviewer: Eager-load skUser.barangay & return photos, narrative, SK Position & Brgy. Name
