Module 01 · Sequence A

Youth Registration Pipeline & Staff/Admin Approval Gate

Traces temporary School ID upload, PSGC hierarchy validation in StoreYouthRegistrationRequest, atomic file promotion, and approval-gated login enforcement.

UploadFileController@tempUpload StoreYouthRegistrationRequest YouthRegistrationController@store Staff/AdminYouthProfileController@approve 
sequenceDiagram
    autonumber
    actor Youth as Youth Applicant
    participant RegUI as Youth Register / Login UI
    participant Upload as UploadFileController
    participant RegCtrl as YouthRegistrationController
    participant StaffCtrl as Staff / Admin YouthProfileController
    participant DB as MySQL (youth_profiles)
    actor Reviewer as MYDO Staff / Admin

    Youth->>RegUI: Fill registration steps & upload School ID (PNG/JPG)
    RegUI->>Upload: POST /temp-upload
    Upload-->>RegUI: Store in public/temp & return filename
    Youth->>RegUI: Submit complete registration payload
    RegUI->>RegCtrl: POST /youth-register
    RegCtrl->>DB: Validate age (15-30), phone format & PSGC city/barangay hierarchy
    RegCtrl->>DB: DB::transaction -> Create YouthProfile (status=pending, is_active=false, ref=YD-XXXX-XXXX)
    RegCtrl->>Upload: Move temp School ID to upfiles/youth-profiles/{id}_{slug}
    RegCtrl-->>RegUI: 200 OK (success=true, account pending MYDO review)

    Reviewer->>StaffCtrl: Inspect pending profile & School ID attachment
    alt Approved
        Reviewer->>StaffCtrl: POST /youth-profiles/{id}/approve
        StaffCtrl->>DB: Set status=approved, is_active=true, approved_by, approved_at
        Youth->>RegUI: Sign in at /youth-login
        RegUI->>DB: YouthAuthController verifies status == approved & is_active == true
        DB-->>RegUI: Authenticate guard('youth') & redirect to /youth/youth-dashboard
    else Rejected
        Reviewer->>StaffCtrl: POST /youth-profiles/{id}/reject (rejection_reason)
        StaffCtrl->>DB: Set status=rejected, is_active=false, rejection_reason
        Youth->>RegUI: Attempt sign in at /youth-login
        RegUI-->>Youth: Deny login & display rejection reason
    end
Module 01 · Sequence B

Dual-Guard Login Routing & Dynamic Multi-Broker Password Reset

Shows role-aware login redirection for Admin, Staff, and SK Officials alongside dynamic broker selection (youths vs users) and CID-embedded logo emails on /forgot-password.

AuthenticatedSessionController EnsureUserHasRole PasswordResetLinkController NewPasswordController emails.password-reset (CID Logos) 
sequenceDiagram
    autonumber
    actor UserActor as User (Youth / Staff / Admin / SK)
    participant AuthUI as Login & Password Reset UI
    participant PwdCtrl as PasswordResetLink & NewPassword Controllers
    participant Broker as Password Broker (youths | users)
    participant SMTP as Gmail SMTP Server
    participant DB as MySQL (users, youth_profiles, password_reset_tokens)

    Note over UserActor, DB: 1. Staff / Admin / SK Portal Login (/login)
    UserActor->>AuthUI: Submit username/email & password at /login
    AuthUI->>DB: Authenticate on web guard (users table)
    DB-->>AuthUI: Resolve User::dashboardRoute() (admin | staff | sk.dashboard.index)
    AuthUI-->>UserActor: Redirect to role workspace protected by EnsureUserHasRole

    Note over UserActor, DB: 2. Dynamic Multi-Broker Forgot Password (/forgot-password)
    UserActor->>AuthUI: Submit email address on /forgot-password
    AuthUI->>PwdCtrl: POST /forgot-password
    PwdCtrl->>DB: Check YouthProfile::where(email) else User::where(email)
    alt Email belongs to YouthProfile
        PwdCtrl->>Broker: Password::broker('youths')->sendResetLink()
    else Email belongs to Admin/Staff/SK User
        PwdCtrl->>Broker: Password::broker('users')->sendResetLink()
    end
    Broker->>DB: Store hashed token in password_reset_tokens
    Broker->>SMTP: Render emails.password-reset with $message->embed() CID logos
    SMTP-->>UserActor: Deliver branded eKabataan Reset Password email

    Note over UserActor, DB: 3. Password Reset Completion (/reset-password)
    UserActor->>AuthUI: Open /reset-password/{token} & submit new password
    AuthUI->>PwdCtrl: POST /reset-password
    PwdCtrl->>Broker: Reset via matching broker ('youths' or 'users')
    Broker->>DB: Save hashed password, update remember_token & delete reset token
    alt Youth Account
        PwdCtrl-->>AuthUI: Redirect to route('youth-login.index')
    else Staff / Admin / SK Account
        PwdCtrl-->>AuthUI: Redirect to route('login')
    end
