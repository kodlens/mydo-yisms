Module 03 · Sequence A

Online Scholarship Application & Real-Time Staff Broadcast

Traces requirement uploads (COE, COG, School ID, Cedula, PSA), duplicate/active-application guards, transactional file promotion, database notification persistence, and live Pusher delivery to all MYDO Staff.

YouthApplyScholarshipController@store NewScholarshipApplicationNotification StaffNotificationBell.tsx 
sequenceDiagram
    autonumber
    actor Youth as Youth Applicant
    participant YouthUI as Apply Scholarship Page
    participant ApplyCtrl as YouthApplyScholarshipController
    participant Disk as Public Storage Disk
    participant DB as MySQL (applications, notifications)
    participant Pusher as Pusher WebSockets
    actor Staff as All MYDO Staff (Live Bell)

    Youth->>YouthUI: Open /youth/services/apply-scholarship/{id}
    Youth->>YouthUI: Upload COE, COG, School ID, Cedula & PSA via /temp-upload
    YouthUI->>Disk: Stage verified files in storage/app/public/temp
    Youth->>YouthUI: Enter previous semester GWA & submit application
    YouthUI->>ApplyCtrl: POST /youth/services/apply-scholarship/{id}

    ApplyCtrl->>DB: Check active AcademicYear & ensure no existing pending/approved application
    alt Duplicate or Active Application Exists
        ApplyCtrl-->>YouthUI: Return 422 JSON error message
    else Eligible to Submit
        ApplyCtrl->>Disk: Move 5 documents to upfiles/scholarships/{youth_id}/{ref}
        ApplyCtrl->>DB: Create ScholarshipApplication (reference=SCH-XXXX, status=pending)
        ApplyCtrl->>DB: Query all Users where role = staff
        ApplyCtrl->>DB: Insert NewScholarshipApplicationNotification in notifications table
        ApplyCtrl-->>Pusher: Broadcast notification payload on private-App.Models.User.{staffId}
        Pusher-->>Staff: Append notification to StaffNotificationBell without page reload
        ApplyCtrl-->>YouthUI: Return 200 OK (reference=SCH-XXXX) & show Submitted modal
    end
Module 03 · Sequence B

Staff / Admin Dossier Review & Real-Time Youth Status Notification

Documents how MYDO Staff or Administrators inspect an applicant's uploaded requirements, approve or reject the scholarship with remarks, record an audit log, and push an instant notification to the Youth's bell.

StaffApplicantController@updateStatus AdminApplicantController@updateStatus ScholarshipApplicationStatusNotification YouthNotificationBell.tsx 
sequenceDiagram
    autonumber
    actor Reviewer as MYDO Staff / Admin
    participant RevUI as Applicant Show Page
    participant AppCtrl as Staff / Admin ApplicantController
    participant DB as MySQL (applications, activity_logs, notifications)
    participant Pusher as Pusher WebSockets
    actor Youth as Youth Applicant (Live Bell)

    Reviewer->>RevUI: Open /staff/applicants/{id} or /admin/applicants/{id}
    RevUI->>AppCtrl: GET applicant dossier
    AppCtrl->>DB: Load ScholarshipApplication + YouthProfile + academicYear + document URLs
    AppCtrl-->>RevUI: Render document viewer & academic profile

    Reviewer->>RevUI: Choose Approve or Reject (encode reason if rejecting)
    RevUI->>AppCtrl: PATCH /applicants/{applicant}/status (status, rejection_reason)
    AppCtrl->>DB: Update status, reviewed_by, reviewed_at, rejection_reason
    AppCtrl->>DB: ActivityLogger::log(scholarship_application_status_updated)
    AppCtrl->>DB: Save ScholarshipApplicationStatusNotification for YouthProfile
    AppCtrl-->>Pusher: Broadcast status update to private-App.Models.YouthProfile.{youthId}
    Pusher-->>Youth: Live alert pops into YouthNotificationBell (Approved / Rejected + reason)
    AppCtrl-->>RevUI: Return updated application status
