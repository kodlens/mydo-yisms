Admin Flow 01

System Taxonomy & User / SK Role Governance

Administrators configure global Activity Categories and Scholarship Types, and manage Staff, Admin, and SK Official accounts (with conditional Barangay assignment and credential resets).

AdminActivityCategoryController AdminScholarshipTypeController AdminUserController 
sequenceDiagram
    autonumber
    actor Admin as System Administrator
    participant UI as Admin Executive Console
    participant ConfigCtrl as Category & ScholarshipType Controllers
    participant UserCtrl as AdminUserController
    participant DB as MySQL (categories, scholarship_types, users, logs)

    Note over Admin, DB: 1. Master Taxonomy Configuration
    Admin->>UI: Manage /admin/activity-categories & /admin/scholarship-types
    UI->>ConfigCtrl: POST / PUT / Toggle Active status
    ConfigCtrl->>DB: Persist ActivityCategory / ScholarshipType changes
    ConfigCtrl-->>UI: Return updated master records

    Note over Admin, DB: 2. User Account & Conditional SK Barangay Management
    Admin->>UI: Open /admin/users & click Add User or Edit User
    alt Selected Role is Staff or Admin
        UI->>UserCtrl: POST /admin/users (username, email, password, role=staff|admin)
        UserCtrl->>DB: Save User (SK address fields set to null)
    else Selected Role is SK Official (role=sk)
        UI->>UI: Reveal SK Position + Province, City & Barangay Leading selects
        UI->>UserCtrl: POST /admin/users (role=sk, sk_position, provCode, citymunCode, brgyCode)
        UserCtrl->>DB: Validate PSGC codes & save User with Barangay jurisdiction
    end
    UserCtrl-->>UI: Refresh User directory showing Role, Position & Brgy. badge

    opt Administrative Password Override
        Admin->>UI: Submit new password for User or Youth Profile
        UI->>UserCtrl: POST /admin/users/{id}/change-password
        UserCtrl->>DB: Hash new password & write ActivityLog (password_change)
        UserCtrl-->>UI: Confirm password updated
    end
Admin Flow 02

Executive Oversight: Youth Profiles, Scholarships & Cash Incentives

Administrators hold full review and disbursement authority over Youth Profiles, Scholarship Applications, and Municipal Cash Incentive Programs.

AdminYouthProfileController AdminApplicantController AdminCashIncentive*Controllers 
sequenceDiagram
    autonumber
    actor Admin as System Administrator
    participant UI as Admin Executive Console
    participant App as Admin Controllers & Services
    participant DB as MySQL Database
    participant Pusher as Pusher WebSockets

    Note over Admin, DB: 1. Youth Profile Approval & Password Control
    Admin->>UI: Open /admin/youth-profiles & inspect Youth Drawer
    UI->>App: POST /admin/youth-profiles/{id}/approve or /reject
    App->>DB: Update YouthProfile status, is_active & write ActivityLog

    Note over Admin, Pusher: 2. Executive Scholarship Application Decision
    Admin->>UI: Open /admin/applicants/{id} & verify uploaded academic files
    UI->>App: PATCH /admin/applicants/{applicant}/status
    App->>DB: Update ScholarshipApplication + write ActivityLog + Youth Notification
    App-->>Pusher: Broadcast ScholarshipApplicationStatusEvent to Youth

    Note over Admin, DB: 3. Cash Incentive Budgeting, Payouts & CSV Export
    Admin->>UI: Create/Edit Program at /admin/cash-incentives
    UI->>App: POST /admin/cash-incentives (ProgramManagementService)
    App->>DB: Create CashIncentiveProgram & log action
    Admin->>UI: Select eligible youth, approve nominations & record batch payouts
    UI->>App: POST /beneficiaries/select, /review & /releases/batch
    App->>DB: Commit beneficiary snapshots, releases & status histories
    Admin->>UI: Export Program Summary or CSV (/reports/export-csv)
    App-->>Admin: Stream CSV / printable beneficiary disbursement report
Admin Flow 03

Admin Events, Live QR Attendance Terminal & Audit Trail Inspection

Administrators manage Events & Activities, operate the 1-click QR/Manual Attendance Check-in Terminal, perform audited attendance removals, and inspect system-wide Activity Logs.

AdminEventActivityController AdminActivityAttendanceController ActivityAttendanceService AdminActivityLogController 
sequenceDiagram
    autonumber
    actor Admin as System Administrator
    participant UI as Admin Events, Attendance & Logs UI
    participant EventCtrl as AdminEvent & Attendance Controllers
    participant Svc as ActivityAttendanceService
    participant LogCtrl as AdminActivityLogController
    participant DB as MySQL (activities, attendances, activity_logs)

    Note over Admin, DB: 1. Event Management & 1-Click Attendance Access
    Admin->>UI: Open /admin/events-activities (loads attendances_count per row)
    Admin->>UI: Create/Update/Feature Activity or review SK Evidence & Sign-ups
    UI->>EventCtrl: POST/PUT /admin/events-activities
    EventCtrl->>DB: Save Activity & write ActivityLog (actor_role=admin)

    Note over Admin, DB: 2. Admin QR / Manual Check-in & Audited Removal
    Admin->>UI: Click Attendance badge -> /admin/events-activities/{id}/attendance
    UI->>EventCtrl: POST /admin/events-activities/{id}/attendance (QR or Manual code)
    EventCtrl->>Svc: recordAttendance(activity, code, method, adminUser)
    Svc->>DB: Lock rows, verify approved registration & insert ActivityAttendance
    Svc-->>UI: Return confirmed check-in card & updated turnout rate
    Admin->>UI: Remove erroneous check-in with mandatory reason (min 5 chars)
    UI->>EventCtrl: DELETE /admin/events-activities/{id}/attendance/{attendanceId}
    EventCtrl->>Svc: removeAttendanceWithAudit(activity, id, adminUser, reason)
    Svc->>DB: Write ActivityLog (activity_attendance.removed, old_values) & delete row

    Note over Admin, DB: 3. System-Wide Activity Log Audit
    Admin->>UI: Open /admin/activity-logs & filter by role, action, or keyword
    UI->>LogCtrl: GET /admin/get-activity-logs & GET /admin/activity-logs/{id}
    LogCtrl->>DB: Query ActivityLog with actor details, IP, user_agent & JSON diffs
    LogCtrl-->>UI: Display chronological audit table & old/new payload inspector
