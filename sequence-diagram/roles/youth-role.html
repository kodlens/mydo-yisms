Youth Flow 01

Online Registration, Approval Gate & Youth Portal Login

Youth applicants upload their School ID and complete registration. Accounts remain locked in pending status until approved by MYDO Staff or an Administrator.

YouthRegistrationController UploadFileController@tempUpload YouthAuthController@login 
sequenceDiagram
    autonumber
    actor Youth as Youth / College Student
    participant UI as Youth Auth UI (Inertia)
    participant Ctrl as YouthAuth & Registration Controllers
    participant Storage as Public Disk Storage
    participant DB as MySQL (youth_profiles)
    actor Staff as MYDO Staff / Admin

    Note over Youth, DB: Phase 1 - Self-Registration with School ID
    Youth->>UI: Open /youth-register & select Province, City, Barangay
    UI->>Ctrl: GET /load-provinces, /load-cities, /load-barangays
    Ctrl-->>UI: Return active PSGC address options
    Youth->>UI: Attach School ID image (PNG/JPG)
    UI->>Ctrl: POST /temp-upload (multipart file)
    Ctrl->>Storage: Store temporary file in storage/app/public/temp
    Ctrl-->>UI: Return temp filename token
    Youth->>UI: Submit Personal, Education & Guardian Form
    UI->>Ctrl: POST /youth-register (StoreYouthRegistrationRequest)
    Ctrl->>DB: Create YouthProfile (status=pending, is_active=false, code=YD-XXXX-XXXX)
    Ctrl->>Storage: Move School ID to upfiles/youth-profiles/{id}_{slug}
    Ctrl-->>UI: Return registration submitted confirmation

    Note over Youth, Staff: Phase 2 - Login Gate Enforcement
    Youth->>UI: Attempt sign-in at /youth-login before approval
    UI->>Ctrl: POST /youth-login
    Ctrl->>DB: Check YouthProfile status & is_active
    alt Status is Pending or Rejected
        Ctrl-->>UI: Block login & show Pending Review / Rejection notice
    else Approved by Staff or Admin
        Staff->>DB: Approve YouthProfile (status=approved, is_active=true)
        Youth->>UI: Submit credentials at /youth-login
        UI->>Ctrl: POST /youth-login
        Ctrl->>DB: Authenticate on guard('youth') & regenerate session
        Ctrl-->>UI: Redirect to /youth/youth-dashboard
    end
Youth Flow 02

Profile Maintenance & Password Recovery

Authenticated youth can update their academic/personal profile and recover forgotten passwords via the dedicated youths password broker and Gmail SMTP.

YouthMyProfileController PasswordResetLinkController NewPasswordController 
sequenceDiagram
    autonumber
    actor Youth as Youth / College Student
    participant UI as Youth Portal / Auth UI
    participant Broker as Laravel Auth Broker (youths)
    participant Mail as Gmail SMTP (CID Logo Email)
    participant DB as MySQL (youth_profiles & tokens)

    Note over Youth, DB: Flow A - Self-Service Profile Update
    Youth->>UI: Open /youth/my-profile & edit contact, school, year, or GWA
    UI->>DB: PUT /youth/my-profile (YouthMyProfileController@update)
    DB-->>UI: Persist updated YouthProfile attributes
    UI-->>Youth: Show profile updated notification

    Note over Youth, DB: Flow B - Forgot Password via Youth Broker
    Youth->>UI: Open /forgot-password & enter registered email
    UI->>Broker: POST /forgot-password (detect YouthProfile email)
    Broker->>DB: Insert hashed token in password_reset_tokens
    Broker->>Mail: Send custom eKabataan HTML email with CID-embedded logos
    Mail-->>Youth: Deliver Reset Password link to inbox
    Youth->>UI: Click /reset-password/{token} & submit new password
    UI->>Broker: POST /reset-password (Password::broker('youths')->reset)
    Broker->>DB: Update YouthProfile password hash & delete token
    UI-->>Youth: Redirect to /youth-login with status message
Youth Flow 03

Scholarships, Events QR Pass, Notifications & Cash Incentives

Core service consumption flow for an approved Youth member across Scholarships, Events & Activities, Real-time Notifications, and the Cash Incentives ledger.

YouthApplyScholarshipController YouthEventActivitiyController YouthCashIncentiveController YouthNotificationController 
sequenceDiagram
    autonumber
    actor Youth as Youth / College Student
    participant Portal as Youth Portal UI + Echo
    participant App as Youth Controllers
    participant DB as MySQL Database
    participant Pusher as Pusher WebSockets

    Note over Youth, Pusher: 1. Scholarship Application & Real-Time Status Alert
    Youth->>Portal: Browse /youth/services/youth-scholarships & click Apply
    Youth->>Portal: Upload COE, COG, School ID, Cedula, PSA via /temp-upload
    Portal->>App: POST /youth/services/apply-scholarship/{id}
    App->>DB: Save ScholarshipApplication (SCH-XXXX, status=pending)
    App-->>Pusher: Notify all MYDO Staff in real time
    Pusher-->>Portal: Later - Receive ScholarshipApplicationStatusEvent (Approved/Rejected)
    Youth->>Portal: Click Notification Bell (/youth/notifications/{id}/read)
    Portal->>App: Mark notification read & display decision remarks

    Note over Youth, DB: 2. Joining an Activity & Presenting QR Event Pass
    Youth->>Portal: Open /youth/services/events-activities & click Join
    Portal->>App: POST /youth/services/events-activities/{activity}/join
    App->>DB: Lock activity row, verify slot capacity & create ActivityRegistration
    App-->>Portal: Confirm registration (Approved or Pending Approval)
    Youth->>Portal: Open QR Event Pass Modal (displays QR for YD-XXXX-XXXX)
    Note right of Youth: Presents QR at venue for Staff/Admin check-in

    Note over Youth, DB: 3. Viewing Cash Incentives Ledger
    Youth->>Portal: Open /youth/cash-incentives (filter by funding year)
    Portal->>App: GET /youth/cash-incentives
    App->>DB: Fetch CashIncentiveBeneficiary & CashIncentiveRelease records
    App-->>Portal: Render grant amounts, approval status & payout ACK details
