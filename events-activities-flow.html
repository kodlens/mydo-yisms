2. Role Interaction & Sequence Diagram

Step-by-step communication between College Student, Staff Organizer, eKabataan Portal, and Database.

sequenceDiagram
    autonumber
    actor Staff as Staff Organizer
    participant Portal as eKabataan Web App
    participant DB as Database (Activities, Registrations, Attendance)
    actor Youth as College Student

    Note over Staff, DB: Phase 1: Event Publication
    Staff->>Portal: Create Activity (Title, Venue, Dates, Capacity: 100)
    Portal->>DB: Save Activity (status = published)

    Note over Youth, DB: Phase 2: Registration
    Youth->>Portal: View /youth/services/events-activities
    Portal->>DB: Query published events & check if youth has registered
    DB-->>Portal: Return events with has_joined and is_approved flags
    Youth->>Portal: Click "Join Activity"
    Portal->>DB: Count current registrations (scopeReservingSlot)
    alt Slot Available
        Portal->>DB: Create ActivityRegistration (status: approved/pending)
        Portal-->>Youth: Return success confirmation ("Joined successfully")
    else Over Capacity
        Portal-->>Youth: Return error ("Capacity reached")
    end

    Note over Staff, DB: Phase 3: On-Site Attendance Check-In
    Youth->>Staff: Present Reference Code (YD-XXXX-XXXX) at registration desk
    Staff->>Portal: Scan QR or search ref code in /staff/activity-attendance
    Portal->>DB: Check ActivityRegistration (must be approved)
    Portal->>DB: Create ActivityAttendance (attended_at: now(), recorded_by: staff_id)
    Portal-->>Staff: Sound confirmation & green participant checkmark

    Note over Youth, Portal: Phase 4: Attendance Verification
    Youth->>Portal: Check Dashboard or Events Page
    Portal-->>Youth: Shows "✓ Attended" badge & increments attended sessions count

3. Registration & Attendance State Machine

Lifecycle of a participant's sign-up from registration to attendance recording.

stateDiagram-v2
    [*] --> SlotChecked: Student clicks Join

    state RegistrationState {
        SlotChecked --> PendingApproval: If event requires approval
        SlotChecked --> Approved: If auto-confirm is enabled
        PendingApproval --> Approved: Staff approves participant
        PendingApproval --> Rejected: Staff rejects participant (slot freed)
        Approved --> Cancelled: Student cancels registration prior to event
    }

    state EventDayAttendance {
        Approved --> Attended: Staff scans QR / checks-in student at venue
        Approved --> Absent: Event concludes without check-in
    }

    state RecordedInProfile {
        Attended --> VerifiedAttendanceRecord: Counts toward student's youth leadership participation
    }
