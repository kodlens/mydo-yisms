2. Role Interaction & Sequence Diagram

Step-by-step communication between Staff/Admin, Database Models, and the Youth Student Portal.

sequenceDiagram
    autonumber
    actor Staff as Staff / Admin
    participant System as eKabataan System
    participant DB as Database (Programs, Beneficiaries, Releases)
    actor Youth as College Student

    Note over Staff, DB: Phase 1: Program Creation & Nomination
    Staff->>System: Create Program (e.g., A.Y. 2026 College Financial Aid, ₱5,000)
    System->>DB: Save CashIncentiveProgram (funding_year = 2026)
    Staff->>System: Filter active college youth & select beneficiaries
    System->>DB: Save snapshot in CashIncentiveBeneficiary (status: pending)
    
    Note over Staff, DB: Phase 2: Evaluation & Release Scheduling
    Staff->>System: Approve nominated beneficiary
    System->>DB: Update beneficiary status = approved
    Staff->>System: Schedule disbursement & set release date
    System->>DB: Create CashIncentiveRelease (status: scheduled)

    Note over Staff, DB: Phase 3: Payout & Acknowledgment
    Staff->>Youth: Disburse cash grant during municipal payout
    Staff->>System: Mark as Released (input actual date & ACK-2026-XXXX)
    System->>DB: Update CashIncentiveRelease (status: released)

    Note over Youth, System: Phase 4: Student Verification
    Youth->>System: Sign in & open "Cash Incentives" module
    System->>DB: Fetch CashIncentiveBeneficiary & Release records for student
    DB-->>System: Return historical records grouped by funding year
    System-->>Youth: Display Ledger (Amount, Status, A.Y. Filter, ACK Ref)

3. Beneficiary & Release State Lifecycle

State machine representation of statuses from nomination to disbursement.

stateDiagram-v2
    [*] --> Nominated: Staff selects student from Youth Registry
    
    state BeneficiaryEvaluation {
        Nominated --> Approved: Staff / Admin approves nomination
        Nominated --> Rejected: Rejected with documented reason
    }
    
    state DisbursementLifecycle {
        Approved --> Scheduled: Release date set by MYDO
        Scheduled --> Disbursed: Cash paid & ACK Reference recorded
        Scheduled --> Unclaimed: Student failed to claim during release window
        Scheduled --> Cancelled: Program cancelled or student forfeited
    }
    
    state StudentPortalView {
        Disbursed --> ViewableOnLedger: Student sees ₱ amount, release date & receipt ref
        Scheduled --> ViewableOnLedger: Student sees "Scheduled for Release"
        Rejected --> ViewableOnLedger: Student sees evaluation status
    }
