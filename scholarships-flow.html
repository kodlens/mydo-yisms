2. Role Interaction & Sequence Diagram

Chronological communication flow between College Student, MYDO Portal, Database, and Admin/Staff Reviewers.

sequenceDiagram
    autonumber
    actor Youth as College Student
    participant Portal as eKabataan Web App
    participant DB as Database (Scholarships, Applications, Logs)
    actor Staff as Staff / Admin Evaluator

    Note over Staff, DB: Phase 1: Program Activation
    Staff->>Portal: Activate Academic Year & Scholarship Type
    Portal->>DB: Save ScholarshipType (is_active = true)

    Note over Youth, DB: Phase 2: Student Application Submission
    Youth->>Portal: Browse /youth/services/youth-scholarships
    Portal->>DB: Query open programs for active Academic Year
    DB-->>Portal: Return available programs & existing application status
    Youth->>Portal: Submit application with COE, COG, ID, Cedula files
    Portal->>DB: Create ScholarshipApplication (reference: #APP-..., status: pending)
    Portal-->>Youth: Return success modal & tracking reference code

    Note over Staff, DB: Phase 3: Staff Document Verification
    Staff->>Portal: Open /staff/applicants or /admin/applicants
    Portal->>DB: Query pending applications with document attachments
    Staff->>Portal: Inspect digital files (COE, COG, Student ID)
    Staff->>Portal: Update status (Approve or Reject with reason)
    Portal->>DB: Update ScholarshipApplication status & reviewed_by
    Portal->>DB: Write to ActivityLog (Action: scholarship_application_status_updated)

    Note over Youth, Portal: Phase 4: Status Inspection
    Youth->>Portal: Visit Dashboard or Scholarships Tracker
    Portal->>DB: Fetch application record with latest status & remarks
    Portal-->>Youth: Display real-time status pill (Approved / Pending / Rejected)

3. Application Status State Machine

State transitions of a student scholarship submission.

stateDiagram-v2
    [*] --> Draft: Student begins application
    Draft --> Pending: Requirements uploaded & submitted
    
    state EvaluationPhase {
        Pending --> UnderReview: Staff opens and inspects attached documents
        UnderReview --> Approved: Verified authentic, passes GWA & residency criteria
        UnderReview --> Rejected: Fails criteria or invalid requirements
    }
    
    state PostEvaluation {
        Approved --> StipendScheduled: Student qualified for scheduled cash release
        Rejected --> ReapplicationAllowed: Student notified with rejection reason
    }
